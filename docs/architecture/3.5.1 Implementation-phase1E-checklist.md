# Implementation Checklist for Phase 1E — Connection, Session, and Identity Foundation

## 1) Scope and boundaries

### In scope
- One connection object per accepted Unix socket
- Per-connection session and connection IDs
- Server-derived peer identity from the trusted Unix socket
- One server-owned `UserContext`
- Connection-scoped shutdown and cancellation
- Active connection registry
- Unit and integration tests

### Out of scope
- Slurm calls
- resource adapters
- command adapters
- authorization policy
- cache and events
- session persistence
- session resumption
- UI behavior
- capability resolution

This matches the architecture boundary described in the Phase 1E design and the existing bridge/dispatcher structure in the project.

## 3) File-by-file task checklist

### A. `internal/connection/connection.go`
Checklist:
- [ ] Define `Connection` with:
  - ID
  - Session
  - Context
  - Cancel
  - state field
- [ ] Add explicit lifecycle state enum or constants:
  - New
  - Active
  - Closing
  - Closed
- [ ] Add constructor such as `NewConnection(...)`
- [ ] Add `Close()` method that:
  - cancels context
  - marks state closed
  - releases connection-scoped resources
- [ ] Ensure no shared state across unrelated socket connections
- [ ] Keep transport/socket fields private unless required for tests

Acceptance:
- each accepted socket gets a distinct `Connection`
- state transitions are explicit
- repeated close is safe

### B. `internal/connection/session.go`
Checklist:
- [ ] Define `Session` with:
  - ID
  - ConnectionID
  - UserContext
- [ ] Create `NewSession(connectionID string, ctx UserContext) *Session`
- [ ] Generate session ID on the server side only
- [ ] Keep session one-to-one with connection for Phase 1E
- [ ] Do not add persistent storage or resumption

Acceptance:
- session ID is non-empty
- session ID differs from connection ID
- one connection = one session

### C. `internal/connection/identity.go`
Checklist:
- [ ] Define `PeerIdentity`:
  - UID
  - GID
  - Username
- [ ] Define `ErrPeerIdentityUnavailable`
- [ ] Implement identity extraction from Unix peer credentials
- [ ] Keep platform-specific logic isolated here
- [ ] On failure, return the sentinel error and do not continue with a privileged context

Acceptance:
- valid Unix socket yields UID/GID/username
- failed retrieval closes the connection
- client cannot override server-derived identity

### D. `internal/connection/user_context.go`
Checklist:
- [ ] Define `UserContext` as the canonical Phase 1E connection context
- [ ] Required fields:
  - UID
  - GID
  - Username
- [ ] Future fields must be intentionally unresolved or absent
- [ ] Ensure zero-value context is not treated as authenticated
- [ ] Build from `PeerIdentity` only
- [ ] Do not create a second `SecurityContext` model

Acceptance:
- `UserContext` is constructed only from server-derived peer data
- empty or failed identity never becomes authorized state

### E. `internal/connection/connection_test.go`
Checklist:

## 4) Test matrix

### Connection lifecycle
- [ ] Accept Unix connection → creates connection object
- [ ] Unique connection IDs among active connections
- [ ] Unique session IDs
- [ ] New → Active → Closing → Closed transitions
- [ ] Normal closure cleanup
- [ ] Double-close is safe
- [ ] Server shutdown closes all active connections

### Identity
- [ ] Successful peer credentials populate UID/GID/username
- [ ] Identity lookup failure closes the connection
- [ ] Client-provided identity is ignored
- [ ] No privilege elevation when identity not available

### UserContext
- [ ] Context created from server-derived identity
- [ ] Zero-value context is rejected
- [ ] No competing `SecurityContext` model is introduced

### Integration
- [ ] Multiple concurrent connections are isolated
- [ ] `hello` continues to work
- [ ] `ping` continues to work
- [ ] Dispatcher errors are still reported through existing protocol semantics

---

## 5) Definition of done

Phase 1E is complete when all of the following are true:
- [ ] Every accepted socket gets a connection object
- [ ] Every connection has a server-generated ID
- [ ] Every connection has a server-generated session ID
- [ ] Peer identity comes only from the Unix socket
- [ ] `UserContext` is the single implementation model
- [ ] Failed identity lookup fails closed
- [ ] No client-supplied identity overrides server values
- [ ] Active connections are cleaned up on shutdown
- [ ] Hello and ping still pass
- [ ] No Slurm logic appears in the connection package
- [ ] `go test ./...` passes
- [ ] `go vet ./...` passes

---

## 6) Recommended implementation order

1. Create the new connection package
2. Add the identity and context types
3. Add the active connection registry
4. Modify the IPC server to construct and register connections
5. Add lifecycle tests
6. Validate hello/ping regression
7. Run Go tests and vet

This order keeps the work small and keeps the architecture from drifting into future authorization and resource tasks.
