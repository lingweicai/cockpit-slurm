# 1. What exactly should Phase 1C implement?

Your Phase 1 implementation plan explicitly defines:

```text
Phase 1B  Unix socket IPC server
      ↓
Phase 1C  Protocol encode/decode
      ↓
Phase 1D  Request dispatcher
      ↓
Phase 1E  Connection/UserContext
```

and says that Phase 1C should make `internal/protocol` closely follow `ipc-protocol.md`. ([GitHub][5])

The important point is that your latest `ipc-protocol.md` defines the transport framing as:

```text
┌──────────────┬───────────────────────┐
│ uint32 length│ UTF-8 JSON payload    │
│ big endian   │                       │
└──────────────┴───────────────────────┘
```

rather than newline-delimited JSON. ([GitHub][2])

That should be the foundation of Phase 1C.

# 4. `internal/protocol/envelope.go`

The current protocol specification requires:

* `protocol`
* `version`
* `messageId`
* `type`
* `timestamp` recommended
* `payload`

and says `payload` is required. ([GitHub][2])

I recommend:

```go
package protocol

import (
	"encoding/json"
	"time"
)

const (
	ProtocolName    = "cockpit-slurm"
	ProtocolVersion = "1.0"
)

// Envelope is the common envelope for every cockpit-slurm IPC message.
type Envelope struct {
	Protocol  string          `json:"protocol"`
	Version   string          `json:"version"`
	MessageID string          `json:"messageId"`
	Type      MessageType     `json:"type"`
	Timestamp string          `json:"timestamp,omitempty"`
	Payload   json.RawMessage `json:"payload"`
}

// NewEnvelope creates a protocol envelope.
func NewEnvelope(messageID string, messageType MessageType, payload json.RawMessage) Envelope {
	return Envelope{
		Protocol:  ProtocolName,
		Version:   ProtocolVersion,
		MessageID: messageID,
		Type:      messageType,
		Timestamp: time.Now().UTC().Format(time.RFC3339),
		Payload:   payload,
	}
}
```

I deliberately use `json.RawMessage` here.

That is important because the envelope should **not know the concrete payload type**.

For example:

```text
Envelope
   │
   ├── hello payload
   ├── ping payload
   ├── query payload
   └── command payload
```

The envelope remains stable.

# 6. Message IDs

Your protocol says every request needs a unique `messageId`, preferably UUID or ULID. ([GitHub][2])

For **Phase 1C**, I would avoid introducing a third-party ULID dependency just for this.

Use a simple internal generator initially:

```go
package protocol

import (
	"crypto/rand"
	"encoding/hex"
	"fmt"
)

func NewMessageID() string {
	var b [16]byte

	if _, err := rand.Read(b[:]); err != nil {
		panic(fmt.Sprintf("generate message ID: %v", err))
	}

	return hex.EncodeToString(b[:])
}
```

Later, if you decide that your architecture requires ULIDs specifically, we can introduce that deliberately.

I don't want Copilot adding a dependency just because the document says "preferably UUID or ULID."

# 7. The most important Phase 1C file: `codec.go`

This is where the protocol becomes real.

Your specification says:

```text
uint32 length
big endian
UTF-8 JSON
```

and explicitly says the protocol must not depend on newline delimiters. ([GitHub][2])

I recommend:

```go
package protocol

import (
	"encoding/binary"
	"encoding/json"
	"errors"
	"fmt"
	"io"
)

const (
	HeaderSize     = 4
	MaxMessageSize = 4 * 1024 * 1024
)

// Encoder writes length-prefixed JSON messages.
type Encoder struct {
	w io.Writer
}

// NewEncoder creates a protocol encoder.
func NewEncoder(w io.Writer) *Encoder {
	return &Encoder{w: w}
}

// Encode writes one complete envelope.
func (e *Encoder) Encode(message Envelope) error {
	payload, err := json.Marshal(message)
	if err != nil {
		return fmt.Errorf("encode JSON: %w", err)
	}

	if len(payload) > MaxMessageSize {
		return fmt.Errorf(
			"message size %d exceeds maximum %d",
			len(payload),
			MaxMessageSize,
		)
	}

	var header [HeaderSize]byte

	binary.BigEndian.PutUint32(header[:], uint32(len(payload)))

	if _, err := e.w.Write(header[:]); err != nil {
		return fmt.Errorf("write message length: %w", err)
	}

	if _, err := e.w.Write(payload); err != nil {
		return fmt.Errorf("write message payload: %w", err)
	}

	return nil
}
```

But there is an important improvement:

**Don't use `Write()` directly and assume it writes everything.**

Use `io.Copy`/`io.WriteString` or, better, `writeFull`.

For a robust implementation:

```go
func writeFull(w io.Writer, data []byte) error {
	for len(data) > 0 {
		n, err := w.Write(data)

		if err != nil {
			return err
		}

		if n == 0 {
			return io.ErrShortWrite
		}

		data = data[n:]
	}

	return nil
}
```

Then:

```go
if err := writeFull(e.w, header[:]); err != nil {
	return fmt.Errorf("write message length: %w", err)
}

if err := writeFull(e.w, payload); err != nil {
	return fmt.Errorf("write message payload: %w", err)
}
```

# 8. Decoder

The decoder needs to be particularly careful because the network/socket is a **stream**, not a message-oriented transport.

```go
package protocol

import (
	"encoding/binary"
	"encoding/json"
	"fmt"
	"io"
)

type Decoder struct {
	r io.Reader
}

// NewDecoder creates a protocol decoder.
func NewDecoder(r io.Reader) *Decoder {
	return &Decoder{r: r}
}

// Decode reads exactly one length-prefixed message.
func (d *Decoder) Decode() (Envelope, error) {
	var envelope Envelope

	var header [HeaderSize]byte

	if _, err := io.ReadFull(d.r, header[:]); err != nil {
		return envelope, fmt.Errorf(
			"read message length: %w",
			err,
		)
	}

	length := binary.BigEndian.Uint32(header[:])

	if length == 0 {
		return envelope, fmt.Errorf("invalid message length: zero")
	}

	if length > MaxMessageSize {
		return envelope, fmt.Errorf(
			"message length %d exceeds maximum %d",
			length,
			MaxMessageSize,
		)
	}

	payload := make([]byte, length)

	if _, err := io.ReadFull(d.r, payload); err != nil {
		return envelope, fmt.Errorf(
			"read message payload: %w",
			err,
		)
	}

	if err := json.Unmarshal(payload, &envelope); err != nil {
		return envelope, fmt.Errorf(
			"decode JSON: %w",
			err,
		)
	}

	if err := ValidateEnvelope(envelope); err != nil {
		return envelope, err
	}

	return envelope, nil
}
```

This directly addresses the protocol's testing requirements for length framing, invalid lengths, oversized messages and invalid JSON. ([GitHub][2])

# 9. `errors.go`

Keep protocol errors separate from the future application error model.

For Phase 1C:

```go
package protocol

import "fmt"

var (
	ErrInvalidProtocol = fmt.Errorf("invalid protocol")
	ErrInvalidVersion  = fmt.Errorf("unsupported protocol version")
	ErrInvalidMessage  = fmt.Errorf("invalid message")
	ErrUnknownMessage  = fmt.Errorf("unsupported message type")
)

func ValidateEnvelope(e Envelope) error {
	if e.Protocol == "" {
		return fmt.Errorf("%w: missing protocol", ErrInvalidProtocol)
	}

	if e.Protocol != ProtocolName {
		return fmt.Errorf(
			"%w: %q",
			ErrInvalidProtocol,
			e.Protocol,
		)
	}

	if e.Version == "" {
		return fmt.Errorf("%w: missing version", ErrInvalidVersion)
	}

	if e.Version != ProtocolVersion {
		return fmt.Errorf(
			"%w: %q",
			ErrInvalidVersion,
			e.Version,
		)
	}

	if e.MessageID == "" {
		return fmt.Errorf("%w: missing messageId", ErrInvalidMessage)
	}

	if e.Type == "" {
		return fmt.Errorf("%w: missing type", ErrInvalidMessage)
	}

	if !e.Type.IsKnown() {
		return fmt.Errorf(
			"%w: %q",
			ErrUnknownMessage,
			e.Type,
		)
	}

	if len(e.Payload) == 0 {
		return fmt.Errorf("%w: missing payload", ErrInvalidMessage)
	}

	return nil
}
```

The eventual error semantics should follow your `error-model.md`; don't let this Phase 1C implementation invent a completely different application error structure.

Your protocol document explicitly calls for tests covering encode/decode, framing, invalid length, oversized messages, invalid JSON and unsupported versions/messages. ([GitHub][2])

func TestEncodeDecode(t *testing.T) {
	payload := json.RawMessage(`{"client":"test"}`)

	msg := NewEnvelope(
		"MSG001",
		MessageHello,
		payload,
	)

	var buf bytes.Buffer

	encoder := NewEncoder(&buf)

	if err := encoder.Encode(msg); err != nil {
		t.Fatal(err)
	}

	decoder := NewDecoder(&buf)

	got, err := decoder.Decode()
	if err != nil {
		t.Fatal(err)

		t.Fatalf("message ID = %q", got.MessageID)

}

# 12. But Phase 1C should eventually replace this

Your current `server.go` handler is:

```go
<-serveCtx.Done()
```

which is only a Phase 1B placeholder. ([GitHub][3])

At the end of Phase 1C, it should become conceptually:

```go
func (s *Server) handleConnection(ctx context.Context, conn net.Conn) {
	defer conn.Close()

	decoder := protocol.NewDecoder(conn)
	encoder := protocol.NewEncoder(conn)

	for {
		message, err := decoder.Decode()
		if err != nil {
			return
		}

		response := handleProtocolMessage(message)

		if err := encoder.Encode(response); err != nil {
			return
		}
	}
}
```

But **I would not put `handleProtocolMessage()` into `ipc.Server`**.

That's the next phase.

Instead, Phase 1C can introduce a tiny protocol-level handler:

```text
internal/protocol/
    handler.go
```

with only:

```text
hello → hello-response
ping  → pong
everything else → protocol "not implemented"
```

That gets us to a useful end-to-end test without prematurely creating the service layer.

# 14. One important correction: `ping` vs `hello`

There is a small evolution in your documents worth making explicit.

The Phase 1 implementation plan initially describes the minimal proof as:

```text
ping → pong
```

while the more complete IPC specification defines a **connection handshake**:

```text
hello
  ↓
hello-response
  ↓
query/subscribe/command...
```

and also defines `ping/pong`. ([GitHub][5])

Therefore I recommend:

### Phase 1C

Implement:

```text
hello → hello-response
ping  → pong
```

but don't yet enforce a complicated connection state machine.

### Phase 1D

Add the dispatcher and enforce:

```text
new connection
      ↓
hello required
      ↓
hello-response
      ↓
normal messages
```

This keeps Phase 1C manageable.
