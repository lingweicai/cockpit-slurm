# 4. A simpler Phase 1B implementation

I would actually recommend this version for your project.

### `internal/ipc/server.go`

```go
package ipc

import (
	"context"
	"errors"
	"fmt"
	"net"
	"os"
	"path/filepath"
	"sync"
)

const DefaultSocketPath = "/run/cockpit-slurm/bridge.sock"

const socketFileMode = 0660

// Server provides a Unix-domain socket listener for cockpit-slurm.
type Server struct {
	socketPath string

	listener net.Listener

	wg sync.WaitGroup

	mu     sync.Mutex
	closed bool
}

// NewServer creates an IPC server.
func NewServer(socketPath string) *Server {
	if socketPath == "" {
		socketPath = DefaultSocketPath
	}

	return &Server{
		socketPath: socketPath,
	}
}

// SocketPath returns the Unix socket path.
func (s *Server) SocketPath() string {
	return s.socketPath
}

// Listen creates and binds the Unix-domain socket.
func (s *Server) Listen() error {
	s.mu.Lock()
	defer s.mu.Unlock()

	if s.listener != nil {
		return errors.New("IPC server is already listening")
	}

	if err := os.MkdirAll(
		filepath.Dir(s.socketPath),
		0755,
	); err != nil {
		return fmt.Errorf("create socket directory: %w", err)
	}

	// A Unix socket leaves a filesystem entry behind after
	// the process exits unexpectedly.
	if err := removeStaleSocket(s.socketPath); err != nil {
		return err
	}

	listener, err := net.Listen("unix", s.socketPath)
	if err != nil {
		return fmt.Errorf(
			"listen on %q: %w",
			s.socketPath,
			err,
		)
	}

	if err := os.Chmod(s.socketPath, socketFileMode); err != nil {
		_ = listener.Close()
		_ = os.Remove(s.socketPath)

		return fmt.Errorf(
			"set socket permissions: %w",
			err,
		)
	}

	s.listener = listener
	s.closed = false

	return nil
}

// Serve accepts connections until the server is closed.
func (s *Server) Serve(ctx context.Context) error {
	s.mu.Lock()
	listener := s.listener
	s.mu.Unlock()

	if listener == nil {
		return errors.New("IPC server is not listening")
	}

	go func() {
		<-ctx.Done()
		_ = s.Close()
	}()

	for {
		conn, err := listener.Accept()
		if err != nil {
			if s.isClosed() {
				return nil
			}

			return fmt.Errorf("accept connection: %w", err)
		}

		s.wg.Add(1)

		go func() {
			defer s.wg.Done()
			defer conn.Close()

			// Phase 1B intentionally does not process
			// application messages.
			//
			// Phase 1C will attach the protocol layer here.
			<-ctx.Done()
		}()
	}
}

// Close stops the server and removes the socket.
func (s *Server) Close() error {
	s.mu.Lock()

	if s.closed {
		s.mu.Unlock()
		return nil
	}

	s.closed = true

	listener := s.listener
	s.listener = nil

	s.mu.Unlock()

	if listener != nil {
		_ = listener.Close()
	}

	s.wg.Wait()

	if err := os.Remove(s.socketPath); err != nil &&
		!errors.Is(err, os.ErrNotExist) {
		return fmt.Errorf("remove socket: %w", err)
	}

	return nil
}

func (s *Server) isClosed() bool {
	s.mu.Lock()
	defer s.mu.Unlock()

	return s.closed
}

func removeStaleSocket(path string) error {
	info, err := os.Lstat(path)

	if errors.Is(err, os.ErrNotExist) {
		return nil
	}

	if err != nil {
		return fmt.Errorf("inspect socket: %w", err)
	}

	if info.Mode()&os.ModeSocket == 0 {
		return fmt.Errorf(
			"socket path %q exists and is not a Unix socket",
			path,
		)
	}

	// We only reach this point when a previous socket file exists.
	//
	// The current Phase 1B implementation removes it and then
	// lets net.Listen() establish the new listener.
	return os.Remove(path)
}
```

This is still more than the DEV.to example, but it is **much more appropriate for your actual architecture**.

# 5. However, there is one important caveat

The simplified version above has this behavior:

```text
existing socket
      ↓
remove it
      ↓
net.Listen()
```

That is fine for a controlled **single-instance systemd service**, but it has a race/operational concern if another Bridge process is actually listening.

Therefore, before production, I would strengthen this part.

For Phase 1B, however, I would **not over-engineer it**.

We can add active-instance protection when we implement the deployment/systemd part.

This is exactly why I would divide:

```text
Phase 1B
Unix socket mechanics

Phase 1B.1
production socket ownership/lifecycle

Phase 1C
protocol
```

rather than putting everything into the first socket implementation.

# 7. One thing I would definitely NOT copy from the DEV.to example

The example does:

```go
if err != nil {
    log.Fatal(err)
}
```

inside the connection goroutine. ([DEV Community][1])

I would **not do this in cockpit-slurm**.

`log.Fatal()` calls `os.Exit(1)` and therefore can terminate the entire Bridge because one client connection encountered an error.

For a long-running system service, that's undesirable.

Instead:

```go
if err != nil {
    log.Printf("connection error: %v", err)
    return
}
```

or eventually let the protocol/session layer return the error to the connection manager.

That's an important production difference.

# 8. I would also not implement echo

The DEV.to example is an **echo server**:

```text
client
  │
  │ "hello"
  ▼
server
  │
  │ "hello"
  ▼
client
```

That's useful for demonstrating sockets. ([DEV Community][1])

But for cockpit-slurm, we shouldn't create an artificial echo protocol.

Instead:

```text
client
   │
   │ protocol message
   ▼
IPC server
   │
   ▼
Phase 1C Protocol Decoder
```

This avoids having to later delete the echo behavior.

# 11. So is my original implementation "better"?

I'd answer:

**Conceptually, yes; as a Phase 1B implementation, it was somewhat over-engineered.**

The DEV.to example is better for understanding the Unix-domain socket mechanism. It demonstrates the essential `Listen → Accept → goroutine → Read/Write → cleanup` pattern very clearly. ([DEV Community][1])

My original implementation was trying to anticipate production concerns too early.

For **your cockpit-slurm project**, I now recommend the middle ground:

```text
DEV.to example
       │
       │  basic socket mechanics
       ▼
  Phase 1B v2
       │
       ├── configurable path
       ├── directory creation
       ├── socket permissions
       ├── concurrent clients
       ├── graceful shutdown
       ├── cleanup
       ├── context
       └── automated tests
       │
       ▼
  Phase 1C
       │
       └── protocol
```

That gives you a **small, understandable, production-oriented foundation without prematurely designing the whole IPC subsystem**.
